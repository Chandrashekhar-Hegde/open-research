1. Run it without an assistant

Start with an executable check. Install Git and Python 3.11+, then run these commands in a terminal. Use python3 if that is your system’s Python command.

git clone https://github.com/Chandrashekhar-Hegde/open-research.git
cd open-research
python research.py doctor
python scripts/verify_workflow.py

The rehearsal uses temporary folders. It installs the skills, imports a browser draft, recalculates real NOAA data, rejects an incomplete input and builds an evidence-linked writing scaffold. It needs no model, account or Python packages.

3. Continue your own study

  1. In the editor, enter your actual question and design decisions. Save editable JSON.
  2. Import that file into a new local folder:
python research.py import-browser /path/to/my-study.study.json studies/my-study
  1. Choose a host in the editor’s local-tools panel and copy the task with your study. Paste it into the session and name studies/my-study as the study folder.
  2. Resolve missing metadata, method choices and access conditions. Require sources, commands and saved outputs when asking for analysis.
  3. Review the artifacts and record verified findings back in Analyze. Save a new JSON backup.

The browser and local folder do not automatically synchronize. Copying a task does not execute work. The website does not upload your study; a tool you paste it into may send context to its model provider.

Installing into another project copies instructions only. Give the host the path to your Open Research checkout for its CLI and examples. See the full terminal guide for another project, automation, custom tools and permissions.

Lurch is the coordinating procedure in agents/lurch.md. It helps choose a stage; it is not a background service. Load one relevant skill rather than asking for a finished paper in one step.

Definitions and assumptions → derivation, boundary cases and numerical or symbolic checks.

When a run does not work

The skill is missing

Check the current directory and installed SKILL.md path. Restart the host, inspect skill permissions and same-name overrides. Ask it to name the loaded file. Reading the canonical skill manually is a fallback, not proof of native discovery.

The answer looks good but nothing ran

Require tool-execution events, actual exit statuses and output files. Run the Python command yourself. Keep the result unverified if execution is unavailable; an expected number repeated in prose is insufficient.

The installer reports a conflict

It preserves modified files. Compare your copy with skills/, retain your changes, and move the conflicting copy before intentionally reinstalling. The installer never changes global accounts or permissions.

The tool cannot run a command

Use the tool’s normal authentication and permission flow. Review the exact operation or execute it yourself. Do not disable safeguards to make a check pass. The core Python workflow remains available without a model.

I use another tool or need terminal automation

Provide the relevant Markdown procedure and its inputs to your tool; discovery syntax varies. The full guide includes claude -p, codex exec, opencode run and custom-directory examples.
